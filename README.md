# Not Myself Cleaning - Elixir/Phoenix

2-я неделя учебной практики (3 курс)

Веб-приложение для клининговой компании на Elixir/Phoenix

## Требования

Для работы с проектом необходимо:
- Elixir 1.16 или выше
- PostgreSQL
- (опционально) Nix для управления окружением

## Быстрый старт

```bash
# Установить зависимости
mix deps.get

# Создать базу данных
mix ecto.create

# Применить миграции
mix ecto.migrate

# Запустить сервер
mix phx.server
```

Приложение будет доступно по адресу: **http://localhost:4000**

## Документация

Полная документация проекта находится в директории `docs/` в формате Jupyter Notebook:

- **04_deployment.ipynb** - установка и развертывание

Подробнее см. [docs/README.md](docs/README.md)

## Структура проекта

```
lib/not_myself_cleaning/          # Бизнес-логика приложения
├── accounts/                     # Модуль работы с пользователями и сессиями
└── requests/                     # Модуль работы с заявками на уборку

lib/not_myself_cleaning_web/      # Веб-слой приложения
├── controllers/                  # Контроллеры (Auth, Request, Admin)
├── router.ex                     # Определение маршрутов
└── endpoint.ex                   # Точка входа HTTP-запросов

priv/repo/migrations/             # Миграции базы данных
priv/static/                      # Статические файлы (CSS, JS, изображения)
```

## Функциональность

Приложение включает следующие возможности:

- Регистрация новых пользователей
- Аутентификация (вход/выход)
- Создание заявок на уборку
- Просмотр истории заявок
- Админ-панель для просмотра всех заявок
- Изменение статусов заявок администратором

## О проекте

Данный проект является переносом существующего приложения с TypeScript/Express ([1-я неделя учебной практики](https://github.com/ZapolyarnyDev/not-myself-cleaning)) на Elixir/Phoenix. В процессе миграции были выполнены следующие изменения:

- Express → Phoenix Framework
- EJS шаблоны → Phoenix HEEx шаблоны
- Репозитории → Ecto контексты
- Command/Query Bus → прямые вызовы контекстов
- Сохранена совместимость с оригинальной схемой базы данных
- Перенесены все статические ресурсы

Подробности см. в [docs/05_migration.ipynb](docs/05_migration.ipynb)
